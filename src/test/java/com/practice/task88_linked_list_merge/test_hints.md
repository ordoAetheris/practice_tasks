# Подсказки: односвязный список + merge (task102)

## Обязательно протестировать
- addLast + toArray — элементы в порядке добавления.
- merge двух непустых отсортированных → один отсортированный, все элементы на месте.
- merge с одним пустым (a=null или b=null) → второй список как есть.
- merge двух пустых → null.
- Дубликаты значений между списками — сохраняются оба (стабильность не требуется, но потерь нет).
- Один список целиком «меньше» другого (хвост дописан целиком).

## Ключевое (в этом суть задачи)
- Проверить, что merge НЕ создаёт новые узлы под данные, а переиспользует существующие:
  сохрани ссылку на конкретный Node из входного списка ДО merge и найди ТОТ ЖЕ объект (по identity `==`)
  в результате.
- O(n+m), без рекурсии на больших входах (или осознанно — обсудить риск StackOverflow при рекурсии).

## Ловушки
- Потеря хвоста при перецеплении next.
- Не обработан случай, когда один из списков закончился раньше (не дописали остаток).
- Создание `new Node(val)` в merge — это уже «с копированием», задача не выполнена.
