# Подсказки: функции-декораторы (task104)

## Обязательно протестировать
- timed: результат обёрнутой функции равен результату оригинала; elapsedSink получил значение >= 0.
- memoize: первый вызов с аргументом X считает; второй вызов с X — из кэша (fn НЕ вызвана снова).
  Счётчик вызовов оригинала (AtomicInteger) для X == 1 после многократных обращений.
- memoize с разными аргументами — каждый считается один раз, значения корректны.

## Ключевое — потокобезопасность memoize
- N потоков одновременно зовут memoized(X) впервые → оригинальная fn вызвана РОВНО ОДИН раз
  (compute-once), все получили одинаковый результат. Прогнать много раз.
- Тяжёлая fn (sleep) под конкуренцией — нет двойного счёта.

## Ловушки
- `computeIfAbsent` + рекурсивный/реентрантный вызов внутри fn → ConcurrentModification/зависание.
- Кэширование null-результата (Map не любит null value — обсудить обёртку Optional/holder).
- Исключение внутри fn — НЕ кэшировать провал (следующий вызов должен пробовать снова).
- timed не должен глотать исключение fn (время можно и не отдавать при ошибке — обсудить).
